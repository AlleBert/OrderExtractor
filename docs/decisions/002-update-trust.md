# ADR 002 · Aggiornamenti firmati e installazione affiancata

Il client usa python-tuf per verificare root, timestamp, snapshot e targets. La root iniziale è inclusa nel pacchetto Windows a build time. Ogni canale mantiene una cache indipendente. Il control plane consegna le risorse solo alle postazioni attive nel canale. Il client invia il token al solo endpoint HTTPS configurato e rifiuta i redirect.

Su Windows installato, il collegamento Start apre un launcher separato. Un aggiornamento confermato dall'utente viene scaricato al prossimo avvio. Il launcher ricontrolla metadati, accesso per canale, versione e hash. L'archivio viene estratto in una directory nuova, con limiti dimensionali e validazione dei percorsi. Prima di eseguire il candidato, il launcher richiede una firma Authenticode valida e confronta il thumbprint con quello della versione attiva. Il candidato prova backend, runtime OCR, SQLite e il frontend in una finestra WebView2 nascosta su una copia, con la diagnostica disattivata. Il servizio di prova accetta la conferma del frontend solo nella sessione locale autenticata e impedisce le modifiche. Il puntatore corrente viene cambiato dopo il controllo e il journal permette di ripristinare il puntatore precedente se il cambio si interrompe.

La prova verifica il frontend sullo snapshot prima del cambio di versione. Eventuali errori che si manifestino solo dopo l’avvio interattivo restano fuori da questa verifica. La distribuzione commerciale richiede il collaudo di installer, certificato, aggiornamento, rollback e isolamento PDF su Windows 11. Dal sorgente è disponibile anche lo scaricamento manuale dell'installer TUF.
